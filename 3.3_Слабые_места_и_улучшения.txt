3.3 СЛАБЫЕ МЕСТА ПРОТОТИПА И ВОЗМОЖНОСТИ УЛУЧШЕНИЯ

3.3.1 Анализ текущих ограничений прототипа

В процессе разработки и тестирования прототипа были выявлены следующие ограничения и слабые места, которые могут быть улучшены в следующих итерациях:

3.3.1.1 Ограничения аппаратной части



2. Ограниченный диапазон ToF-сенсоров:
   - Максимальный диапазон: 4 метра
   - Причина: технические ограничения VL53L1X сенсоров
   - Влияние: невозможность следования на больших расстояниях (>4 м)

3. Зависимость от интернет-соединения:
   - Текущая архитектура требует постоянного интернет-соединения для связи с наземной станцией
   - Причина: использование облачного backend сервера
   - Влияние: невозможность работы в зонах без интернета, задержки из-за сетевой латентности

4. Ограниченная вычислительная мощность:
   - Raspberry Pi 5 имеет ограниченную производительность для сложных нейронных сетей
   - Причина: ARM процессор без специализированного AI-ускорения
   - Влияние: ограничение на сложность моделей детекции, невозможность использования более точных но тяжёлых моделей



3.3.1.2 Ограничения программного обеспечения

1. Простые PID-регуляторы:
   - Используются только пропорциональные компоненты (P-регуляторы)
   - Причина: упрощение для первой итерации
   - Влияние: возможны статические ошибки, менее плавное управление

2. Отсутствие предсказания движения цели:
   - Система реагирует только на текущее положение объекта
   - Причина: упрощение алгоритма
   - Влияние: задержка реакции при быстром движении цели, возможна потеря цели

3. Ограниченная обработка потери цели:
   - При потере цели дрон просто зависает на месте
   - Причина: отсутствие алгоритма поиска
   - Влияние: невозможность восстановления слежения без вмешательства оператора

4. Отсутствие построения карты окружения:
   - Система не строит карту препятствий
   - Причина: использование только двух ToF-сенсоров (вперёд и вниз)
   - Влияние: невозможность обхода препятствий сбоку, риск столкновения

5. Отсутствие адаптации к условиям освещения:
   - Алгоритм не адаптируется к изменению освещения
   - Причина: фиксированные параметры детекции
   - Влияние: снижение точности детекции при плохом освещении

3.3.2 Улучшения аппаратной части

3.3.2.1 Увеличение времени полёта

Проблема: ограниченное время полёта из-за энергопотребления.

Решения:

1. Использование более энергоэффективного бортового компьютера:
   - Вариант A: NVIDIA Jetson Nano (оптимизирован для AI, но всё ещё потребляет ~5-10 Вт)
   - Вариант C: Специализированные AI-ускорители (Google Coral, Intel Neural Compute Stick) для оффлоада нейронной сети

2. Оптимизация энергопотребления:
   - Отключение неиспользуемых периферийных устройств
   - Снижение частоты процессора когда возможно
   - Использование режимов энергосбережения

3. Увеличение ёмкости батареи:
   - Использование батарей большей ёмкости (с учётом увеличения веса)
   - Оптимизация веса конструкции для размещения большей батареи


Ожидаемый результат: увеличение времени полёта до 30-40 минут.

3.3.2.2 Расширение диапазона измерения расстояний

Проблема: ограничение ToF-сенсоров до 4 метров.

Решения:

1. Использование более дальнобойных сенсоров:
   - VL53L5CX: диапазон до 8 метров (но больше размеры и стоимость)
   - LiDAR сенсоры: диапазон до 100+ метров (но значительно дороже и больше)
   - Стереокамера: оценка расстояния до 10+ метров (но требует больше вычислений)

2. Комбинированный подход:
   - ToF-сенсор для малых расстояний (0-4 м) - высокая точность
   - Стереокамера или LiDAR для больших расстояний (4-20 м) - средняя точность
   - Переключение между сенсорами в зависимости от расстояния

3. Улучшение оценки расстояния по размеру объекта:
   - Калибровка модели для конкретного типа объектов
   - Использование машинного обучения для более точной оценки
   - Комбинирование визуальной оценки с данными сенсоров

Ожидаемый результат: возможность следования на расстояниях до 10-15 метров.

3.3.2.3 Устранение зависимости от интернета

Проблема: необходимость постоянного интернет-соединения.

Решения:

1. Локальный backend сервер:
   - Размещение backend на локальном компьютере оператора
   - Использование Wi-Fi Direct или ad-hoc сети для связи
   - Устранение зависимости от облачных сервисов


3. Автономный режим:
   - Реализация полностью автономного режима без связи с оператором
   - Дрон работает по предзаданной программе или полностью автономно
   - Связь используется только для мониторинга, не для критичного управления

Ожидаемый результат: возможность работы без интернета, снижение задержки управления.

3.3.2.4 Увеличение вычислительной мощности

Проблема: ограниченная производительность Raspberry Pi для сложных задач.

Решения:

1. Использование AI-ускорителей:
   - Google Coral USB Accelerator: специализированный TPU для нейронных сетей
   - Intel Neural Compute Stick 2: VPU для ускорения инференса
   - NVIDIA Jetson Nano: встроенный GPU с CUDA поддержкой

2. Оптимизация моделей:
   - Квантизация моделей (INT8 вместо FP32) для ускорения
   - Использование TensorRT или ONNX Runtime с оптимизацией
   - Pruning и distillation моделей для уменьшения размера

3. Обновление до более мощного компьютера:
   - NVIDIA Jetson Orin Nano: значительно более мощный, но дороже
   - Использование облачных вычислений для сложных задач (но увеличивает задержку)

Ожидаемый результат: возможность использования более точных моделей (YOLO11s, YOLO11m) или обработка видео в более высоком разрешении.


3.3.2.6 Добавление дополнительных сенсоров

Для улучшения возможностей дрона можно добавить:

1. Стереокамера:
   - Позволяет строить карту глубины (depth map)
   - Оценка расстояний до всех объектов в поле зрения
   - Возможность обхода препятствий

2. Дополнительные ToF-сенсоры:
   - Сенсоры по бокам для обнаружения препятствий сбоку
   - Сенсор назад для безопасного движения назад
   - 360° покрытие для полного понимания окружения

3. IMU с более высокой точностью:
   - Более точное определение ориентации
   - Улучшение стабильности полёта
   - Возможность работы без внешних датчиков (optical flow, GPS)

4. Оптический поток (Optical Flow):
   - Определение скорости относительно земли без GPS
   - Улучшение позиционирования в помещении
   - Стабилизация зависания

5. Ультразвуковой дальномер:
   - Дополнительная проверка высоты (резервный сенсор)
   - Работа в условиях, где ToF может давать сбои (пыль, туман)

3.3.3 Улучшения программного обеспечения

3.3.3.1 Улучшение PID-регуляторов

Проблема: использование только пропорциональных компонентов.

Решения:

1. Реализация полных PID-регуляторов:
   - Добавление интегральной компоненты для устранения статической ошибки
   - Добавление дифференциальной компоненты для уменьшения колебаний
   - Настройка параметров для каждого режима полёта

2. Адаптивные PID-регуляторы:
   - Автоматическая настройка параметров в зависимости от условий
   - Разные параметры для разных скоростей движения цели
   - Адаптация к характеристикам конкретного дрона

3. Каскадные регуляторы:
   - Внешний контур: позиционирование относительно цели
   - Внутренний контур: стабилизация ориентации
   - Улучшение точности и плавности управления

Математическая модель полного PID:

```
u(t) = Kp * e(t) + Ki * ∫e(τ)dτ + Kd * de(t)/dt
```

С защитой от windup интегральной компоненты:

```
I = I + Ki * e * dt
I = clamp(I, -I_max, I_max)  // Ограничение интеграла
```

Ожидаемый результат: более точное и плавное управление, устранение статических ошибок.

3.3.3.2 Предсказание движения цели

Проблема: реакция только на текущее положение, задержка при быстром движении.

Решения:

1. Фильтр Калмана для предсказания:
   - Оценка скорости и ускорения цели
   - Предсказание будущего положения
   - Компенсация задержки системы

Математическая модель:

Состояние цели:
```
x = [px, py, vx, vy]^T
```

Модель движения (constant velocity):
```
x[k+1] = F * x[k] + w[k]
```

где:
```
F = [1  0  dt  0 ]
    [0  1  0   dt]
    [0  0  1   0 ]
    [0  0  0   1 ]
```

Предсказание на N шагов вперёд:
```
x_predicted[k+N] = F^N * x[k]
```

2. Экстраполяция траектории:
   - Построение полиномиальной модели траектории
   - Экстраполяция на основе истории движений
   - Учёт возможных изменений направления

3. Машинное обучение для предсказания:
   - Обучение модели на данных о движении людей
   - Предсказание наиболее вероятного направления движения
   - Учёт контекста (препятствия, направление взгляда человека)

Ожидаемый результат: плавное следование даже при быстром движении цели, снижение вероятности потери цели.

3.3.3.3 Алгоритм поиска потерянной цели

Проблема: при потере цели дрон просто зависает.

Решения:

1. Поиск по последнему известному направлению:
   - Запоминание последнего направления движения цели
   - Поворот дрона в этом направлении
   - Поиск цели в расширенном поле зрения

2. Спиральный поиск:
   - Дрон движется по спирали от последней известной позиции
   - Постепенное увеличение радиуса поиска
   - Остановка при обнаружении цели или достижении максимального радиуса

Математическая модель спирального поиска:

Параметрическое уравнение спирали:
```
r(θ) = r0 + k * θ
x(θ) = r(θ) * cos(θ)
y(θ) = r(θ) * sin(θ)
```

где:
- r0 - начальный радиус
- k - коэффициент увеличения радиуса
- θ - угол (увеличивается со временем)

3. Использование истории движений:
   - Анализ паттернов движения цели
   - Предсказание наиболее вероятного местоположения
   - Направленный поиск в предсказанном направлении

4. Координация с оператором:
   - Запрос помощи у оператора при потере цели
   - Оператор указывает направление поиска
   - Автоматическое возобновление слежения при обнаружении

Ожидаемый результат: автоматическое восстановление слежения без вмешательства оператора в большинстве случаев.

3.3.3.4 Построение карты препятствий

Проблема: отсутствие информации о препятствиях сбоку.

Решения:

1. Использование стереокамеры:
   - Построение карты глубины (depth map)
   - Обнаружение препятствий во всех направлениях
   - Планирование траектории обхода

2. SLAM (Simultaneous Localization and Mapping):
   - Построение карты окружения в реальном времени
   - Одновременная локализация дрона на карте
   - Планирование безопасных траекторий

Алгоритм:
- Использование визуальной одометрии (visual odometry)
- Построение sparse или dense карты
- Обновление карты при движении

3. Использование дополнительных ToF-сенсоров:
   - Массив сенсоров для 360° покрытия
   - Простое построение карты расстояний
   - Быстрое обнаружение препятствий

4. Планирование траектории:
   - Алгоритм A* или RRT для планирования пути
   - Обход препятствий с сохранением слежения за целью
   - Динамическое перепланирование при изменении окружения

Ожидаемый результат: безопасное движение в сложной среде с препятствиями, автоматический обход препятствий.

3.3.3.5 Адаптация к условиям освещения

Проблема: снижение точности при плохом освещении.

Решения:

1. Автоматическая настройка параметров камеры:
   - Автоматическая регулировка экспозиции (AE)
   - Автоматический баланс белого (AWB)
   - Автоматическая регулировка усиления (AGC)

2. Предобработка изображений:
   - Гистограммная эквализация для улучшения контраста
   - Фильтрация шума (bilateral filter, non-local means)
   - Улучшение изображения в условиях низкой освещённости

3. Адаптация порогов детекции:
   - Динамическое изменение порога уверенности в зависимости от условий
   - Использование адаптивных порогов вместо фиксированных
   - Калибровка на основе статистики детекций

4. Использование инфракрасной камеры:
   - Дополнительная камера для работы в темноте
   - Переключение между камерами в зависимости от условий
   - Комбинирование данных от обеих камер

5. Обучение модели на различных условиях:
   - Data augmentation с различным освещением
   - Обучение модели, устойчивой к изменениям освещения
   - Использование transfer learning для адаптации

Ожидаемый результат: стабильная работа в широком диапазоне условий освещения.

3.3.3.6 Улучшение алгоритма детекции

Текущие улучшения:

1. Использование более точных моделей:
   - Переход с YOLO11n на YOLO11s или YOLO11m
   - Использование специализированных моделей для детекции людей
   - Fine-tuning на данных из реальных полётов

2. Мультимасштабная детекция:
   - Детекция на нескольких масштабах изображения
   - Улучшение обнаружения объектов разных размеров
   - Комбинирование результатов от разных масштабов

3. Временная согласованность:
   - Использование информации из предыдущих кадров
   - Фильтрация ложных срабатываний на основе временной согласованности
   - Предсказание позиций объектов между кадрами

4. Контекстная информация:
   - Учёт контекста сцены для улучшения детекции
   - Использование информации о типе окружения
   - Фильтрация невозможных детекций на основе контекста

3.3.4 Интеграция улучшений

3.3.4.1 Приоритизация улучшений

Для эффективного развития прототипа рекомендуется следующая последовательность внедрения улучшений:

Фаза 1 (Критичные улучшения):
1. Улучшение PID-регуляторов (полные PID)
2. Предсказание движения цели (фильтр Калмана)
3. Алгоритм поиска потерянной цели

Фаза 2 (Важные улучшения):
4. Устранение зависимости от интернета (локальный backend)
6. Адаптация к условиям освещения

Фаза 3 (Расширенные возможности):
7. Построение карты препятствий (SLAM)
8. Добавление дополнительных сенсоров
9. Увеличение времени полёта

3.3.4.2 Оценка сложности внедрения

Улучшения сгруппированы по сложности внедрения:

Низкая сложность (1-2 недели):
- Улучшение PID-регуляторов
- Адаптация к условиям освещения
- Улучшение алгоритма поиска

Средняя сложность (1-2 месяца):
- Предсказание движения цели
- Устранение зависимости от интернета
- Улучшение защиты от EMI

Высокая сложность (3-6 месяцев):
- Построение карты препятствий (SLAM)
- Интеграция дополнительных сенсоров
- Значительные изменения аппаратной части

3.3.5 Заключение по разделу

В данном разделе были проанализированы слабые места текущего прототипа и предложены конкретные пути улучшения как аппаратной, так и программной части системы.

Основные направления улучшений:

1. Аппаратная часть:
   - Увеличение времени полёта через оптимизацию энергопотребления
   - Расширение возможностей сенсоров
   - Улучшение защиты от помех
   - Устранение зависимости от интернета

2. Программное обеспечение:
   - Улучшение алгоритмов управления (полные PID, предсказание)
   - Расширение возможностей (поиск цели, обход препятствий)
   - Адаптация к различным условиям работы
   - Повышение надёжности и безопасности

Предложенные улучшения позволят создать более надёжную, функциональную и автономную систему следования за объектами, пригодную для практического применения в различных сценариях использования.

Реализация улучшений должна выполняться поэтапно с тестированием каждого этапа, чтобы обеспечить стабильность работы системы и возможность отката к предыдущей версии при возникновении проблем.
