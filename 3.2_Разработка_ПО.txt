3.2 РАЗРАБОТКА ПРОГРАММНОГО ОБЕСПЕЧЕНИЯ

3.2.1 Архитектура программного обеспечения

Программное обеспечение прототипа автономного дрона построено по клиент-серверной архитектуре с разделением на три основных компонента:

1. Backend сервер (FastAPI + WebSocket)
2. Frontend веб-интерфейс (React)
3. Drone Client (Python) - бортовое ПО на Raspberry Pi

3.2.2 Backend сервер (FastAPI)

Backend сервер реализован на базе FastAPI - современного веб-фреймворка для Python с поддержкой асинхронных операций и WebSocket соединений.

3.2.2.1 Архитектура Backend

Backend сервер выполняет роль релея сообщений между дроном и веб-клиентами. Основные компоненты:

1. ConnectionManager - управление WebSocket соединениями
2. WebSocket endpoint - обработка входящих соединений
3. Message routing - маршрутизация сообщений между клиентами

Ключевые особенности реализации:

- Разделение клиентов на два типа: "drone" (дрон) и "web" (веб-интерфейс)
- Автоматическая маршрутизация: команды от веб-клиентов → дрону, телеметрия от дрона → всем веб-клиентам
- Обработка разрывов соединений с автоматической очисткой неактивных подключений

3.2.2.2 Структура сообщений

Все сообщения передаются в формате JSON через WebSocket:

Формат команды от веб-клиента:
```json
{
  "source": "web",
  "type": "command",
  "command": "arm",
  "payload": {}
}
```

Формат телеметрии от дрона:
```json
{
  "source": "drone",
  "type": "telemetry",
  "data": {
    "altitude": 1.5,
    "battery": 85.0,
    "mode": "ALT_HOLD",
    "armed": true,
    ...
  }
}
```

3.2.3 Frontend веб-интерфейс (React)

Frontend реализован как одностраничное приложение (SPA) на React с использованием современных хуков и функциональных компонентов.

3.2.3.1 Архитектура Frontend

Основные компоненты:

1. useDroneWebSocket - кастомный хук для управления WebSocket соединением
2. ControlPanel - панель управления дроном (arm, disarm, takeoff, land, etc.)
3. TelemetryPanel - отображение телеметрии в реальном времени
4. PersonTracker - интерфейс для выбора объекта для отслеживания
5. DistanceModeSelector - выбор режима расстояния следования (в текущей версии не используется)

3.2.3.2 Управление состоянием

Состояние приложения управляется через:
- React hooks (useState, useEffect)
- Custom events для передачи данных между компонентами
- WebSocket для связи с backend

Пример обработки команд:
```javascript
const handleCommand = (action) => {
  setStatus(prev => ({ ...prev, [key]: 'sending' }));
  sendCommand(action);
};
```

3.2.4 Drone Client - бортовое программное обеспечение

Drone Client представляет собой наиболее сложную часть системы, объединяющую обработку компьютерного зрения, управление дроном, работу с сенсорами и связь с наземной станцией.

3.2.4.1 Архитектура Drone Client

Drone Client построен по модульной архитектуре с разделением на следующие подсистемы:

1. **Vision System** (Система компьютерного зрения):
   - CameraManager - управление камерой
   - YOLODetector - детекция объектов нейронной сетью
   - ObjectTracker - отслеживание объектов между кадрами

2. **Control System** (Система управления):
   - DroneController - управление дроном через MAVLink
   - TrackingController - контроллер следования за объектом
   - TelemetryReader - чтение телеметрии от полётного контроллера

3. **Sensor System** (Система сенсоров):
   - ToFSensorManager - управление ToF-сенсорами
   - TelemetryCollector - сбор и агрегация телеметрии

4. **Communication System** (Система связи):
   - WebSocketClient - связь с backend сервером

Архитектурная схема Drone Client:

3.2.5 Алгоритм следования за объектом

Алгоритм следования за объектом является ключевым компонентом системы. Он реализован в классе TrackingController и использует комбинацию компьютерного зрения, датчиков расстояния и PID-регуляторов для плавного и точного следования.

3.2.5.1 Общая схема алгоритма

Алгоритм работает в несколько этапов:

1. **Захват кадра** (CameraManager):
   - Частота: 30 FPS
   - Разрешение: 640×480 пикселей
   - Формат: RGB888

2. **Детекция объектов** (YOLODetector):
   - Модель: YOLO11n (ONNX)
   - Входное разрешение: 320×320 пикселей
   - Порог уверенности: 0.5
   - Выход: список детекций с bounding boxes и классами

3. **Отслеживание объектов** (ObjectTracker):
   - Алгоритм: DeepSORT или простой IoU-based tracker
   - Назначение: поддержание ID объектов между кадрами
   - Выход: отслеживаемые детекции с постоянными ID

4. **Выбор цели** (TrackingController):
   - Пользователь выбирает объект по ID через веб-интерфейс
   - Контроллер запоминает выбранный ID

5. **Расчёт команд управления** (TrackingController):
   - Определение позиции объекта в кадре
   - Измерение расстояния до объекта (ToF-сенсор или оценка по размеру bbox)
   - Расчёт ошибок по осям (yaw, pitch, distance, altitude)
   - Применение PID-регуляторов для расчёта команд скорости

6. **Отправка команд** (DroneController):
   - Преобразование команд в формат MAVLink
   - Отправка velocity commands в режиме ALT_HOLD

Блок-схема алгоритма следования:

```
┌─────────────┐
│  Capture    │
│   Frame     │
└──────┬──────┘
       │

┌─────────────┐
```

3.2.5.2 Математическая модель следования

Позиционирование объекта в кадре:

Пусть кадр имеет размеры W×H пикселей (640×480). Центр кадра:
```
C_frame = (W/2, H/2) = (320, 240)
```

Позиция объекта в кадре определяется центром bounding box:
```
P_obj = (x_obj, y_obj)
```

Ошибка позиционирования по горизонтали (для управления yaw):
```
e_x = x_obj - W/2
```

Ошибка позиционирования по вертикали (для управления pitch/altitude):
```
e_y = y_obj - H/2
```

Нормализованные ошибки (в диапазоне [-1, 1]):
```
e_x_norm = e_x / (W/2) = 2 * e_x / W
e_y_norm = e_y / (H/2) = 2 * e_y / H
```

Преобразование ошибок в угловые:

Учитывая поле зрения камеры (FOV), ошибка в пикселях преобразуется в угловую ошибку:

Горизонтальная угловая ошибка:
```
θ_error_x = e_x_norm * (FOV_horizontal / 2)
```

где FOV_horizontal = 120° (из конфигурации).

В радианах:
```
θ_error_x_rad = e_x_norm * (π * FOV_horizontal / 360)
```

Вертикальная угловая ошибка:
```
θ_error_y_rad = e_y_norm * (π * FOV_vertical / 360)
```

где FOV_vertical = 90°.

3.2.5.3 Управление по yaw (горизонтальное центрирование)

Для центрирования объекта по горизонтали используется пропорциональный регулятор:

```
yaw_rate = -Kp_yaw * θ_error_x_rad
```

где:
- Kp_yaw = 0.5 (коэффициент пропорциональности, настраивается)
- Знак минус обеспечивает правильное направление поворота

Ограничение yaw_rate:
```
yaw_rate = clamp(yaw_rate, -0.5, 0.5) rad/s
```

3.2.5.4 Управление расстоянием (поддержание заданного расстояния)

Целевое расстояние до объекта: d_target = 3.0 м (фиксированное значение).

Текущее расстояние измеряется передним ToF-сенсором:
```
d_current = reading_from_forward_tof_sensor
```

Если ToF-сенсор недоступен или выдаёт невалидное значение, используется оценка по размеру bounding box (см. раздел 3.2.5.6).

Ошибка расстояния:
```
e_distance = d_current - d_target
```

Команда скорости по оси X (вперёд/назад):
```
vx = -Kp_distance * e_distance
```

где:
- Kp_distance = 0.2 (коэффициент пропорциональности)
- Знак минус: при положительной ошибке (объект дальше цели) дрон движется вперёд (отрицательная скорость в системе координат дрона)

Ограничения скорости:
```
vx = clamp(vx, -1.0, 1.0) m/s
```

Безопасность: если объект слишком близко (d_current < 0.8 м), команда vx устанавливается в 0 (экстренная остановка).

3.2.5.5 Управление высотой (вертикальное центрирование и поддержание высоты)

Управление высотой комбинирует два компонента:

1. Вертикальное центрирование объекта в кадре (pitch control)
2. Поддержание заданной высоты над землёй (altitude control)

Вертикальное центрирование:

Команда скорости по вертикали для центрирования:
```
vz_pitch = -Kp_pitch * θ_error_y_rad
```

где Kp_pitch = 0.3.

Поддержание высоты:

Целевая высота: h_target = 1.5 м (AGL - Above Ground Level).

Текущая высота измеряется нижним ToF-сенсором:
```
h_current = reading_from_bottom_tof_sensor
```

Ошибка высоты:
```
e_altitude = h_target - h_current
```

Команда скорости для поддержания высоты:
```
vz_altitude = Kp_altitude * e_altitude * 0.1
```

где:
- Kp_altitude = 15.0 (высокий коэффициент для быстрой реакции)
- Множитель 0.1 для масштабирования

Комбинированная команда по вертикали:
```
vz = vz_altitude + vz_pitch * 0.3
```

Приоритет отдаётся поддержанию высоты (коэффициент 0.3 для pitch компонента).

Ограничения:
```
vz = clamp(vz, -0.5, 0.5) m/s
```

3.2.5.6 Оценка расстояния по размеру bounding box

В случае недоступности ToF-сенсора используется оценка расстояния на основе размера объекта в кадре.

Математическая модель:

Используется модель пinhole камеры. Расстояние до объекта связано с размером объекта в кадре следующим соотношением:

```
d = (f * H_real) / H_pixels
```

где:
- d - расстояние до объекта (метры)
- f - фокусное расстояние в пикселях
- H_real - реальная высота объекта (метры)
- H_pixels - высота объекта в пикселях

Фокусное расстояние в пикселях рассчитывается из поля зрения:

```
f_pixels = H_image / (2 * tan(FOV_vertical / 2))
```

где:
- H_image = 480 пикселей (высота кадра)
- FOV_vertical = 90° = π/2 радиан

Подставляя значения:
```
f_pixels = 480 / (2 * tan(π/4)) = 480 / (2 * 1) = 240 пикселей
```

Для горизонтального измерения:
```
f_pixels_h = W_image / (2 * tan(FOV_horizontal / 2))
         = 640 / (2 * tan(π/3))
         = 640 / (2 * √3)
         ≈ 185 пикселей
```

Оценка расстояния по высоте объекта:

Если известна реальная высота объекта H_real (например, для стула ~1.0 м), то:
```
d_height = (f_pixels * H_real) / H_bbox
        = (240 * 1.0) / H_bbox
```

где H_bbox - высота bounding box в пикселях.

Оценка расстояния по ширине объекта:

Аналогично, если известна реальная ширина объекта W_real (для стула ~0.5 м):
```
d_width = (f_pixels_h * W_real) / W_bbox
        = (185 * 0.5) / W_bbox
```

Итоговая оценка:
```
d_estimated = (d_height + d_width) / 2
```

Ограничение оценки:
```
d_estimated = clamp(d_estimated, 0.5, 20.0) метров
```

3.2.5.7 Сглаживание команд (Smoothing)

Для уменьшения колебаний и обеспечения плавного движения применяется экспоненциальное сглаживание:

```
v_smooth(t) = α * v_smooth(t-1) + (1 - α) * v_calculated(t)
```

где:
- α = 0.7 (коэффициент сглаживания, настраивается)
- v_smooth(t-1) - сглаженная скорость на предыдущем шаге
- v_calculated(t) - рассчитанная скорость на текущем шаге

Применяется ко всем компонентам скорости:
- vx_smooth
- vy_smooth (обычно 0, так как roll не используется)
- vz_smooth
- yaw_rate_smooth

3.2.5.8 Преобразование координат (Body Frame → NED Frame)

Команды скорости рассчитываются в системе координат дрона (body frame), где:
- X - вперёд
- Y - вправо
- Z - вверх

Полётный контроллер ArduPilot использует систему координат NED (North-East-Down), где:
- X (North) - на север
- Y (East) - на восток
- Z (Down) - вниз (положительное направление вниз!)

Преобразование выполняется с учётом текущего курса дрона (heading):

```
heading_rad = heading_deg * π / 180
```

Компоненты скорости в NED:
```
v_north = vx_body * cos(heading_rad) - vy_body * sin(heading_rad)
v_east  = vx_body * sin(heading_rad) + vy_body * cos(heading_rad)
v_down  = -vz_body  // Инверсия знака!
```

3.2.6 PID-регуляторы

В системе используются пропорциональные (P) регуляторы с возможностью расширения до полных PID-регуляторов.

3.2.6.1 Структура PID-регулятора

Классический PID-регулятор описывается формулой:

```
u(t) = Kp * e(t) + Ki * ∫e(τ)dτ + Kd * de(t)/dt
```

где:
- u(t) - управляющее воздействие
- e(t) - ошибка (разница между заданным и текущим значением)
- Kp - коэффициент пропорциональности
- Ki - коэффициент интегральный
- Kd - коэффициент дифференциальный

В дискретном виде (для реализации в коде):

```
u[k] = Kp * e[k] + Ki * Σe[i] * Δt + Kd * (e[k] - e[k-1]) / Δt
```

где:
- k - номер шага
- Δt - интервал времени между шагами

3.2.6.2 Текущие настройки PID

В текущей реализации используются только пропорциональные компоненты (P-регуляторы):

Yaw (горизонтальное центрирование):
- Kp = 0.5
- Ki = 0.0
- Kd = 0.1

Pitch (вертикальное центрирование):
- Kp = 0.3
- Ki = 0.0
- Kd = 0.05

Distance (поддержание расстояния):
- Kp = 0.2
- Ki = 0.0
- Kd = 0.1

Altitude (поддержание высоты):
- Kp = 15.0
- Ki = 0.5
- Kd = 5.0

3.2.6.3 Настройка PID-параметров

Настройка PID-параметров выполняется эмпирически методом проб и ошибок:

1. Начальные значения выбираются на основе опыта и литературы
2. Тестирование на реальном дроне
3. Анализ поведения (перерегулирование, колебания, медленная реакция)
4. Корректировка параметров

Правила настройки:

- Увеличение Kp: более быстрая реакция, но возможны колебания
- Увеличение Ki: устранение статической ошибки, но возможен windup
- Увеличение Kd: уменьшение колебаний, но чувствительность к шуму

3.2.7 Обработка потери цели

При потере объекта в поле зрения камеры система должна реагировать безопасно.

Алгоритм обработки потери цели:

1. Отслеживание времени последней детекции:
```
t_last_detection = current_time
```

2. Проверка таймаута:
```
if (current_time - t_last_detection) > timeout_lost_target:
    stop_tracking()
    enter_loiter_mode()
```

где timeout_lost_target = 2.0 секунды (из конфигурации).

3. При потере цели:
   - Остановка следования
   - Переход в режим LOITER (висение на месте)
   - Ожидание повторного обнаружения или команды оператора

3.2.8 Система безопасности

В системе реализованы несколько уровней безопасности:

1. **Проверки перед взлётом (Pre-arm checks)**:
   - Проверка наличия ToF-сенсоров (обязательны для полёта)
   - Проверка уровня батареи
   - Проверка режима полёта

2. **Ограничения расстояния**:
   - Минимальное расстояние: 0.8 м (экстренная остановка)
   - Порог только yaw: 2.0 м (только поворот, без движения вперёд)
   - Порог препятствия: 1.5 м (блокировка движения вперёд)

3. **Ограничения высоты**:
   - Минимальная высота: 0.5 м
   - Максимальная высота: 2.0 м (принудительное ограничение)

4. **Мониторинг батареи**:
   - Предупреждение при 30%
   - Критический уровень: 20%
   - Автоматическая посадка при 15%
