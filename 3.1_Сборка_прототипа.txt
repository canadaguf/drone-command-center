ГЛАВА 3. РАЗРАБОТКА

3.1 СБОРКА ПРОТОТИПА

3.1.1 Общая архитектура аппаратной части

Прототип автономного дрона для следования за объектами представляет собой квадрокоптер, оснащённый бортовым компьютером на базе одноплатного компьютера Raspberry Pi, системой компьютерного зрения, датчиками расстояния и полётным контроллером. Архитектура прототипа построена по модульному принципу, что обеспечивает гибкость в настройке и возможность модернизации отдельных компонентов без переделки всей системы.

Основные подсистемы прототипа:
1. Полётная платформа (квадрокоптер)
2. Полётный контроллер (ArduPilot)
3. Бортовой компьютер (Raspberry Pi)
4. Система компьютерного зрения (камера + нейронная сеть)
5. Система измерения расстояний (ToF-сенсоры)
6. Система связи (WebSocket через интернет)

3.1.2 Выбор и обоснование комплектующих

3.1.2.1 Полётная платформа

В качестве базовой платформы был выбран квадрокоптер стандартной X-конфигурации с четырьмя бесколлекторными двигателями. Выбор квадрокоптера обусловлен следующими факторами:

- Стабильность полёта: квадрокоптер обеспечивает высокую стабильность по сравнению с трикоптерами или гексакоптерами при меньшей сложности конструкции
- Грузоподъёмность: достаточная для размещения всех необходимых компонентов (Raspberry Pi, камера, датчики, батарея)
- Маневренность: достаточная для следования за движущимися объектами
- Доступность запчастей: широкий выбор совместимых компонентов

Технические характеристики полётной платформы:
- Тип: квадрокоптер X-конфигурация
- Диаметр пропеллеров: 10 дюймов (254 мм)
- Рама: карбоновая или алюминиевая, обеспечивающая жёсткость и минимальный вес
- Масса без полезной нагрузки: ~1050 г
- Максимальная взлётная масса: ~2000-2500 г

3.1.2.2 Полётный контроллер ArduPilot

В качестве полётного контроллера выбран ArduPilot, установленный на платформе типа Pixhawk или совместимой. ArduPilot представляет собой открытую прошивку для автономных летательных аппаратов с развитой экосистемой и активным сообществом разработчиков.

Обоснование выбора ArduPilot:

1. Функциональность:
   - Поддержка множества режимов полёта (ALT_HOLD, LOITER, GUIDED, LAND и др.)
   - Встроенная система безопасности (pre-arm checks, geofence, failsafe)
   - Расширенный фильтр Калмана (EKF) для оценки состояния
   - Поддержка MAVLink протокола для связи с внешними системами

2. Гибкость настройки:
   - Возможность тонкой настройки PID-регуляторов для всех осей
   - Поддержка различных типов датчиков через MAVLink DISTANCE_SENSOR сообщения
   - Возможность работы без GPS в режиме ALT_HOLD (критично для полётов в помещении)

3. Надёжность:
   - Проверенная временем прошивка с миллионами часов наработки
   - Активное сообщество и постоянные обновления
   - Хорошая документация

4. Совместимость:
   - Поддержка DroneKit и pymavlink библиотек для Python
   - Стандартизированный протокол MAVLink
   - Возможность интеграции с внешними системами

Технические характеристики полётного контроллера:
- Процессор: STM32F4 или совместимый (ARM Cortex-M4, 168 МГц)
- Память: Flash 2 МБ, RAM 192 КБ
- Интерфейсы: UART (для связи с Raspberry Pi), I2C, SPI, CAN
- Датчики: акселерометр, гироскоп, магнитометр, барометр
- Протокол связи: MAVLink v2.0
- Скорость связи с Raspberry Pi: 256000 бод (настроено для минимальной задержки)

3.1.2.3 Бортовой компьютер Raspberry Pi

В качестве бортового компьютера выбран Raspberry Pi 5. Raspberry Pi обеспечивает достаточную вычислительную мощность для работы нейронной сети детекции объектов в реальном времени, обработки видеопотока и управления всеми подсистемами дрона.

Обоснование выбора Raspberry Pi:

1. Вычислительная мощность:
   - Процессор: Broadcom BCM2711 (4 ядра ARM Cortex-A72, 1.5-1.8 ГГц)
   - Оперативная память: 8 ГБ LPDDR4 (достаточно для работы нейронной сети и обработки видео)
   - GPU: VideoCore VI с поддержкой аппаратного ускорения для обработки видео

2. Интерфейсы:
   - GPIO: для подключения датчиков и управления периферией
   - I2C: для подключения ToF-сенсоров через мультиплексор
   - CSI: для подключения камеры Raspberry Pi Camera Module
   - UART: для связи с полётным контроллером
   - USB: для дополнительных устройств
   - Ethernet/Wi-Fi: для связи с наземной станцией

3. Экосистема:
   - Широкая поддержка библиотек для компьютерного зрения (OpenCV, Picamera2)
   - Поддержка нейронных сетей (ONNX Runtime, TensorFlow Lite)
   - Активное сообщество разработчиков
   - Хорошая документация

4. Энергоэффективность:
   - Потребление: ~3-5 Вт в режиме активной работы
   - Возможность питания от батареи дрона через регулятор напряжения

5. Надёжность:
   - Проверенная платформа с миллионами экземпляров в продакшене
   - Поддержка microSD карт для хранения ОС и данных
   - Возможность работы в расширенном температурном диапазоне (с охлаждением)

Технические характеристики Raspberry Pi:
- Модель: Raspberry Pi 5
- Процессор: 4 ядра ARM Cortex-A72/A76, 1.5-2.4 ГГц
- ОЗУ: 8 ГБ LPDDR4
- Хранилище: microSD карта 32+ ГБ (класс 10 или выше)
- Операционная система: Raspberry Pi OS (Debian-based) или Ubuntu Server
- Потребление: 3-5 Вт (без периферии)

3.1.2.4 Система компьютерного зрения

Система компьютерного зрения состоит из камеры и программного обеспечения для детекции объектов на базе нейронной сети YOLO11.

Камера: Raspberry Pi Camera Module 3

Выбор камеры Raspberry Pi Camera Module 3 обусловлен следующими факторами:

1. Интеграция:
   - Прямое подключение через CSI интерфейс (Camera Serial Interface)
   - Низкая задержка передачи данных
   - Оптимизированная библиотека Picamera2 для работы с камерой

2. Технические характеристики:
   - Разрешение: до 11.9 МП (4608×2592) в режиме фото, 1080p@30fps в режиме видео
   - Используемое разрешение: 640×480 пикселей @ 30 fps (оптимально для баланса качества и производительности)
   - Угол обзора: 120° по горизонтали, 90° по вертикали (широкоугольный объектив)
   - Формат: RGB888 для обработки нейронной сетью
   - Автофокус: поддерживается (для улучшения качества детекции)

3. Производительность:
   - Низкая задержка захвата кадра (<50 мс)
   - Стабильная частота кадров
   - Хорошее качество изображения при достаточном освещении

4. Надёжность:
   - Защищённый разъём CSI
   - Стабильная работа в условиях вибрации
   - Широкий температурный диапазон работы

Нейронная сеть: YOLO11n (nano версия)

Для детекции объектов используется модель YOLO11n (You Only Look Once version 11 nano) в формате ONNX. YOLO11 представляет собой современную архитектуру детекции объектов, оптимизированную для работы в реальном времени на мобильных и встраиваемых устройствах.

Обоснование выбора YOLO11n:

1. Производительность:
   - Скорость инференса: ~20-30 FPS на Raspberry Pi 5 (при разрешении 320×320)
   - Точность: mAP@0.5 > 0.5 для класса "person" (COCO dataset)
   - Размер модели: ~6 МБ (ONNX формат), что позволяет хранить модель на устройстве

2. Архитектура:
   - Однопроходная детекция (single-stage detector) - быстрее двухпроходных методов
   - Оптимизация для мобильных устройств
   - Поддержка ONNX Runtime для эффективного выполнения

3. Гибкость:
   - Возможность обучения на кастомных датсетах
   - Поддержка различных классов объектов (в текущей реализации - детекция стульев для безопасного тестирования)
   - Возможность переключения на детекцию людей для продакшн использования

Технические характеристики модели:
- Архитектура: YOLO11n (nano)
- Формат: ONNX (Open Neural Network Exchange)
- Входное разрешение: 320×320 пикселей
- Порог уверенности: 0.5 (50%)
- Порог NMS: 0.4
- Целевой класс: COCO class 56 (chair) - для безопасного тестирования
- Размер модели: ~6 МБ

3.1.2.5 Система измерения расстояний (ToF-сенсоры)

Для измерения расстояний до объектов и высоты над землёй используются два Time-of-Flight (ToF) сенсора VL53L1X производства STMicroelectronics. Эти сенсоры используют лазерный луч для измерения расстояния методом времени пролёта, обеспечивая высокую точность и быстродействие.

Обоснование выбора VL53L1X:

1. Технические характеристики:
   - Диапазон измерения: 0.04 м - 4.0 м (40 мм - 4000 мм)
   - Точность: ±5% в диапазоне 0.4-4 м
   - Разрешение: 1 мм
   - Частота измерений: до 50 Гц
   - Время измерения: ~20-30 мс

2. Преимущества перед ультразвуковыми датчиками:
   - Высокая точность (особенно на малых расстояниях)
   - Быстрое время отклика
   - Нечувствительность к акустическим помехам
   - Компактные размеры
   - Низкое энергопотребление (~20 мА)

3. Преимущества перед LiDAR:
   - Низкая стоимость
   - Компактность
   - Низкое энергопотребление
   - Достаточный диапазон для задач следования за объектами

Конфигурация ToF-сенсоров:

1. Передний сенсор (forward):
   - Назначение: измерение расстояния до отслеживаемого объекта
   - Расположение: направлен вперёд по курсу дрона
   - Диапазон: 0.3-4.0 м (оптимальный для следования на расстоянии 3 м)
   - Использование: поддержание заданного расстояния до цели

2. Нижний сенсор (down/bottom):
   - Назначение: измерение высоты над землёй (AGL - Above Ground Level)
   - Расположение: направлен вертикально вниз
   - Диапазон: 0.04-4.0 м
   - Использование: контроль высоты при взлёте, посадке и полёте

Мультиплексор I2C: TCA9548A

Поскольку оба VL53L1X сенсора имеют одинаковый I2C адрес (0x29 по умолчанию), для их одновременного использования необходим I2C мультиплексор. Выбран TCA9548A (или PCA9548A) - 8-канальный I2C мультиплексор производства Texas Instruments.

Обоснование выбора TCA9548A:

1. Функциональность:
   - 8 независимых каналов I2C
   - Возможность подключения до 8 устройств с одинаковым адресом
   - Программное переключение каналов
   - Прозрачность для устройств (устройства не знают о наличии мультиплексора)

2. Технические характеристики:
   - Адрес мультиплексора: 0x70 (по умолчанию, настраивается через A0-A2 пины)
   - Скорость I2C: до 400 кГц (в проекте используется 100 кГц для лучшей устойчивости к EMI)
   - Напряжение питания: 2.3-5.5 В
   - Потребление: <1 мА

3. Надёжность:
   - Встроенные подтягивающие резисторы
   - Защита от обратного тока
   - Широкий температурный диапазон

Схема подключения ToF-сенсоров:

```
Raspberry Pi                    TCA9548A                    VL53L1X Sensors
┌─────────────┐                ┌─────────────┐            ┌─────────────┐
│             │                │             │            │             │
│ Pin 1 (3.3V)├───────────────┤ VIN         │            │             │
│ Pin 3 (SDA) ├───────────────┤ SDA         │            │             │
│ Pin 5 (SCL) ├───────────────┤ SCL         │            │             │
│ Pin 6 (GND) ├───────────────┤ GND         │            │             │
│             │                │             │            │             │
└─────────────┘                │ SD0/SC0    ├────────────┤ Forward     │
                               │            │            │ Sensor      │
                               │ SD1/SC1    ├────────────┤ Down        │
                               │            │            │ Sensor      │
                               └─────────────┘            └─────────────┘
```

3.1.2.6 Система связи

Для связи между дроном и наземной станцией управления используется WebSocket соединение через интернет. Это позволяет управлять дроном удалённо и получать телеметрию в реальном времени.

Архитектура связи:

1. Дрон (Raspberry Pi):
   - WebSocket клиент, подключается к backend серверу
   - Отправляет телеметрию и данные детекции
   - Принимает команды управления

2. Backend сервер:
   - FastAPI приложение с WebSocket поддержкой
   - Релеирует сообщения между дроном и веб-клиентами
   - Размещается на облачной платформе (Render.com)

3. Веб-интерфейс:
   - React приложение
   - WebSocket клиент для связи с backend
   - Отображение телеметрии и видео с детекциями
   - Отправка команд управления

Преимущества WebSocket:
- Двусторонняя связь в реальном времени
- Низкая задержка
- Поддержка бинарных данных (для видео)
- Автоматическое переподключение при разрыве связи

3.1.3 Сложные места при сборке

3.1.3.1 Подключение ToF-сенсоров через мультиплексор

Одной из наиболее сложных задач при сборке прототипа является правильное подключение двух ToF-сенсоров через I2C мультиплексор. Основные сложности:

1. Проблема одинаковых I2C адресов:
   - Оба VL53L1X сенсора имеют адрес 0x29 по умолчанию
   - Прямое подключение обоих к одной I2C шине невозможно без мультиплексора
   - Решение: использование TCA9548A мультиплексора для изоляции сенсоров на разных каналах

2. Электромагнитные помехи (EMI):
   - Работающие моторы дрона создают сильные электромагнитные помехи
   - I2C шина чувствительна к помехам, что может приводить к ошибкам чтения
   - Решение: снижение скорости I2C с 400 кГц до 100 кГц для повышения устойчивости
   - Дополнительно: использование экранированных проводов и правильное заземление

3. Проблемы с переключением каналов:
   - Неправильное переключение каналов может приводить к чтению данных с неправильного сенсора
   - Необходимо добавлять задержки после переключения канала для стабилизации
   - Решение: реализация retry-логики с экспоненциальной задержкой при ошибках EAGAIN

4. Питание сенсоров:
   - Оба сенсора должны получать стабильное питание 3.3 В
   - Недостаточное питание может приводить к нестабильной работе
   - Решение: использование отдельной линии питания от стабилизатора напряжения, а не напрямую от Raspberry Pi

3.1.3.2 Интеграция Raspberry Pi с полётным контроллером

Связь между Raspberry Pi и полётным контроллером осуществляется через UART интерфейс с использованием протокола MAVLink. Основные сложности:

1. Настройка UART на Raspberry Pi:
   - По умолчанию UART на Raspberry Pi используется для консоли (serial console)
   - Необходимо отключить serial console и настроить UART для связи с внешним устройством
   - Решение: редактирование файла /boot/config.txt и /boot/cmdline.txt

2. Скорость передачи данных:
   - Высокая скорость передачи (256000 бод) необходима для минимальной задержки команд
   - Не все UART интерфейсы Raspberry Pi поддерживают такие скорости стабильно
   - Решение: использование основного UART (/dev/ttyAMA0) с правильной настройкой

3. Синхронизация данных:
   - Необходима синхронизация между данными от полётного контроллера и данными от сенсоров
   - Задержки в передаче могут приводить к неточностям в управлении
   - Решение: использование временных меток и буферизация данных

4. Обработка ошибок связи:
   - Разрыв связи с полётным контроллером должен обрабатываться gracefully
   - Необходимо реализовать механизмы переподключения и fallback режимы
   - Решение: реализация watchdog таймеров и автоматического переподключения

3.1.3.3 Размещение компонентов на дроне

Правильное размещение всех компонентов на дроне критично для стабильности полёта и работы систем. Основные требования:

1. Центр масс:
   - Центр масс дрона должен совпадать с геометрическим центром рамы
   - Неправильное распределение массы приводит к нестабильности полёта
   - Решение: размещение тяжёлых компонентов (Raspberry Pi, батарея) в центре рамы

2. Защита от вибраций:
   - Вибрации от моторов могут повредить электронные компоненты
   - Вибрации влияют на работу камеры и датчиков
   - Решение: использование демпфирующих материалов (поролон, силикон) для изоляции компонентов

3. Охлаждение:
   - Raspberry Pi и полётный контроллер выделяют тепло при работе
   - Перегрев может приводить к нестабильной работе или отказу
   - Решение: использование радиаторов и обеспечение воздушного потока (вентиляция)

4. Размещение камеры:
   - Камера должна быть направлена вперёд по курсу дрона
   - Не должно быть препятствий в поле зрения камеры
   - Решение: размещение камеры на передней части рамы с возможностью регулировки угла наклона

5. Размещение ToF-сенсоров:
   - Передний сенсор должен быть направлен строго вперёд
   - Нижний сенсор должен быть направлен строго вниз
   - Сенсоры не должны затеняться другими компонентами
   - Решение: размещение сенсоров на выносных кронштейнах для обеспечения чистого поля зрения

3.1.3.4 Электропитание системы

Обеспечение стабильного электропитания всех компонентов является критически важной задачей. Основные сложности:

1. Разные напряжения питания:
   - Моторы: обычно 3S или 4S LiPo батарея (11.1 В или 14.8 В)
   - Raspberry Pi: требуется 5 В (через USB-C или GPIO)
   - Полётный контроллер: обычно питается от батареи через BEC (Battery Eliminator Circuit)
   - ToF-сенсоры: требуют 3.3 В
   - Решение: использование регуляторов напряжения (BEC для Raspberry Pi, LDO для сенсоров)

2. Потребление тока:
   - Raspberry Pi: ~2-3 А при полной нагрузке
   - Полётный контроллер: ~0.5 А
   - ToF-сенсоры: ~0.1 А
   - Камера: ~0.2 А
   - Общее потребление: ~3-4 А (без учёта моторов)
   - Решение: использование BEC с достаточным током (5 А или выше)

3. Защита от перепадов напряжения:
   - Работа моторов создаёт перепады напряжения в системе питания
   - Перепады могут повредить чувствительные компоненты
   - Решение: использование конденсаторов большой ёмкости (1000+ мкФ) для сглаживания напряжения

4. Мониторинг батареи:
   - Необходимо отслеживать уровень заряда батареи для предотвращения разряда ниже критического уровня
   - Решение: использование встроенного мониторинга батареи полётного контроллера через MAVLink

3.1.4 Обоснованность выбора комплектующих

3.1.4.1 Сравнение с альтернативными решениями

Полётный контроллер:

Альтернатива 1: PX4
- Преимущества: более современная архитектура, лучшая поддержка новых функций
- Недостатки: менее стабильная для полётов в помещении без GPS, меньшая поддержка сообщества
- Выбор: ArduPilot выбран из-за лучшей поддержки ALT_HOLD режима и стабильности

Альтернатива 2: Betaflight (для FPV дронов)
- Преимущества: очень низкая задержка, оптимизация для гоночных дронов
- Недостатки: отсутствие поддержки автономных режимов, нет поддержки MAVLink
- Выбор: не подходит для задач автономного следования

Бортовой компьютер:

Альтернатива 1: NVIDIA Jetson Nano
- Преимущества: более мощный GPU, лучше для работы с нейронными сетями
- Недостатки: значительно выше стоимость, большее энергопотребление, больше размеры
- Выбор: Raspberry Pi выбран из-за оптимального соотношения цена/производительность/энергопотребление

Альтернатива 2: Orange Pi или другие клоны
- Преимущества: часто ниже стоимость
- Недостатки: хуже поддержка, меньше документации, проблемы с совместимостью
- Выбор: Raspberry Pi выбран из-за лучшей экосистемы и поддержки

Камера:

Альтернатива 1: USB веб-камера
- Преимущества: простота подключения, широкий выбор моделей
- Недостатки: большая задержка, необходимость USB интерфейса, большее энергопотребление
- Выбор: Raspberry Pi Camera Module выбран из-за низкой задержки и оптимизации

Альтернатива 2: IP-камера
- Преимущества: возможность беспроводной передачи видео
- Недостатки: очень большая задержка, зависимость от Wi-Fi, сложность интеграции
- Выбор: не подходит для задач реального времени

ToF-сенсоры:

Альтернатива 1: Ультразвуковые датчики (HC-SR04)
- Преимущества: очень низкая стоимость, простота подключения
- Недостатки: низкая точность, медленное время отклика, чувствительность к помехам
- Выбор: VL53L1X выбран из-за высокой точности и быстродействия

Альтернатива 2: LiDAR (например, RPLidar)
- Преимущества: возможность построения карты окружения, большой диапазон
- Недостатки: очень высокая стоимость, большое энергопотребление, большие размеры
- Выбор: не требуется для задачи следования за объектом

3.1.4.3 Техническое обоснование

Выбранные компоненты обеспечивают:

1. Производительность:
   - Обработка видео: 30 FPS @ 640×480
   - Детекция объектов: 20-30 FPS (YOLO11n на Raspberry Pi 4)
   - Частота управления: 20 Гц (команды управления дроном)
   - Частота телеметрии: 2 Гц (отправка данных на наземную станцию)

2. Точность:
   - Детекция объектов: mAP@0.5 > 0.5
   - Измерение расстояния: ±5% в диапазоне 0.4-4 м
   - Контроль высоты: ±5 см (при использовании ToF-сенсора)

3. Надёжность:
   - Время работы: ограничено ёмкостью батареи (обычно 10-20 минут)
   - Устойчивость к сбоям: автоматическое переподключение при разрыве связи
   - Безопасность: встроенные механизмы безопасности ArduPilot (pre-arm checks, failsafe)

3.1.5 Заключение по разделу

В результате проведённого анализа и сборки прототипа была создана аппаратная платформа автономного дрона для следования за объектами. Выбранные компоненты обеспечивают необходимую функциональность при оптимальном соотношении цена/производительность. Модульная архитектура позволяет легко модернизировать отдельные компоненты без переделки всей системы.

Основные достижения:
- Создана работоспособная аппаратная платформа
- Решены технические сложности с подключением множественных I2C устройств
- Обеспечена стабильная работа всех подсистем
- Достигнута необходимая производительность для работы в реальном времени

Выявленные ограничения:
- Ограниченное время полёта из-за энергопотребления Raspberry Pi
- Зависимость от интернет-соединения для связи с наземной станцией
- Ограниченный диапазон ToF-сенсоров (до 4 м)

Эти ограничения будут рассмотрены в разделе 3.3 как направления для улучшения в следующих итерациях прототипа.
